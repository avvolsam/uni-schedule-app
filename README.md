# Расписание университета (РАНХиГС СПб)

PWA-приложение с расписанием занятий, которое само подтягивает свежие данные с сайта
`spb.ranepa.ru` — без App Store/Google Play, просто добавляется на домашний экран
iPhone и Android прямо из браузера.

## Как это устроено

Расписание обновляется тремя способами:

1. **Каждый час автоматически.** GitHub Actions (`.github/workflows/update-and-deploy.yml`)
   раз в час запускает `scripts/fetch-schedule.mjs`, который забирает все расписания через
   встроенный в сайт WordPress REST API (`/wp-json/wp/v2/raspisanie`), парсит таблицы
   и таксономии, раскладывает результат по `public/data/*.json` и публикует сайт на
   GitHub Pages. Час включает и 06:00 по Москве. GitHub может запускать такие задачи
   с опозданием на 5–30 минут. Бесплатно, без своего сервера.
2. **Кнопка ↻ в приложении — прямо сейчас.** Телефон студента сам обращается к
   `spb.ranepa.ru` (тем же API), разбирает таблицы тем же кодом (`shared/`) и показывает
   то, что на сайте в эту секунду. Работает для любого студента, не нагружая GitHub.
   Если сайт напрямую недоступен, показывается последняя версия из часовой сборки.
   Приложение также само проверяет сайт при открытии (не чаще раза в 15 минут).
3. **Заметка об изменениях.** Каждый раз, когда приходят новые данные, приложение
   сравнивает их с тем, что было у студента раньше, и показывает баннер «Расписание
   изменилось»: что добавили, что отменили или перенесли, где сменилась аудитория или
   преподаватель.

Устройство проекта:

- **`shared/`** — код, общий для скрипта сборки и приложения: разбор таблиц
  (`parseSchedule.mjs`), сравнение версий расписания (`diffLessons.mjs`), очистка от
  дублей и сортировка (`normalizeLessons.mjs`).
- **`scripts/`** — загрузка данных (`fetch-schedule.mjs`) и офлайн-тесты.
- **`src/`** — приложение (React + Vite + `vite-plugin-pwa`): при первом запуске просит
  один раз выбрать направление и группу (сохраняется в `localStorage` телефона), при
  каждом следующем открытии сразу показывает расписание этой группы. Работает офлайн по
  последнему сохранённому расписанию.

4. **Push-уведомления при закрытом приложении** (через OneSignal). После каждой часовой
   сборки `scripts/notify-changes.mjs` сравнивает новые расписания с прошлым запуском
   (снимок хранится в кэше GitHub Actions) и отправляет уведомление только подписанным
   на изменившуюся группу. Настройка — в разделе «Уведомления» ниже.

## Уведомления (OneSignal), настройка один раз

1. Зарегистрируйтесь на [onesignal.com](https://onesignal.com) (бесплатно) и создайте
   приложение типа **Web** → интеграция **Typical Site / Custom Code**. В поле Site URL
   укажите адрес сайта **без пути**: `https://<ваш-логин>.github.io`. Иконка — файл
   `public/icons/icon-512.png`. Инструкции по установке SDK пропустите: код уже написан.
2. В OneSignal откройте **Settings → Keys & IDs** и возьмите:
   - **App ID** — публичный идентификатор (не секрет);
   - **REST API Key** — **секрет**, никому не показывайте и никуда не вставляйте, кроме
     пункта 3.
3. В репозитории GitHub: **Settings → Secrets and variables → Actions**:
   - вкладка **Variables** → New repository variable: имя `ONESIGNAL_APP_ID`, значение — App ID;
   - вкладка **Secrets** → New repository secret: имя `ONESIGNAL_REST_API_KEY`, значение —
     REST API Key.
4. Запустите workflow вручную (Actions → Run workflow). Сайт пересоберётся с включённой
   кнопкой «Включить уведомления». Без пункта 3 кнопка просто скрыта.

Как это устроено: студент нажимает «Включить уведомления» → браузер подключает OneSignal и
помечает устройство меткой `group=<код группы>` → при изменении расписания этой группы
сервер отправляет уведомление по метке. На iPhone работает только для приложения на экране
«Домой» (iOS 16.4+).

## Безопасность и приватность

- **Секреты не лежат в коде.** REST API Key хранится только в GitHub Secrets и передаётся
  единственному шагу сборки, который отправляет уведомления; в логи и в опубликованный
  сайт он не попадает. В `.gitignore` добавлены `.env*`. Публичный App ID секретом не
  является — он виден каждому посетителю сайта (так устроен OneSignal).
- **Никаких аккаунтов и персональных данных.** Выбранная группа и расписание хранятся
  только в `localStorage` телефона. Приложение не спрашивает имя, почту, телефон.
- **OneSignal подключается только по желанию.** Пока студент не нажал «Включить», обращений к
  OneSignal нет вообще. После включения OneSignal получает анонимный идентификатор устройства
  и метку группы.
- **Защита от подмены данных на экране.** Данные сайта выводятся как обычный текст (React
  экранирует его), разбор таблиц берёт только текст ячеек; `innerHTML`/`eval` не используются.
- **Защита от ложных массовых уведомлений.** Если за час «изменилась» половина университета
  или число групп/занятий резко упало, рассылка блокируется (скорее всего сбой источника).
- **Права CI минимальны.** Каждому заданию GitHub Actions выданы только нужные права; в
  workflow используются только официальные `actions/*`. `npm audit`: 0 уязвимостей.
- **Ограничения.** Скрипт OneSignal подгружается с их CDN без проверки контрольной суммы
  (у версионного «плавающего» файла её нет), а данные о студентах-подписчиках обрабатывает
  внешний сервис. Репозиторий публичный: не храните в нём ничего, кроме кода.

## Развёртывание (один раз)

Нужен бесплатный аккаунт на [github.com](https://github.com) — на нём и будет жить сайт
и ежедневное обновление.

1. Создайте новый **публичный** репозиторий на GitHub (например, `uni-schedule`).
2. Загрузите в него содержимое этой папки:
   ```bash
   git init
   git add .
   git commit -m "Initial commit"
   git branch -M main
   git remote add origin https://github.com/<ваш-логин>/<repo>.git
   git push -u origin main
   ```
3. В репозитории откройте **Settings → Pages** и в разделе "Build and deployment"
   выберите источник **GitHub Actions** (не "Deploy from a branch").
4. Откройте вкладку **Actions**, найдите workflow «Update schedule and deploy» и
   нажмите **Run workflow** (первый запуск не по расписанию, а вручную) — он заберёт
   данные, соберёт сайт и опубликует его. Это займёт 1–2 минуты.
5. После успешного запуска сайт будет доступен по адресу
   `https://<ваш-логин>.github.io/<repo>/` (ссылку также показывает вкладка Actions →
   последний run → Deploy).

Дальше обновление происходит само каждый час. А если нужно прямо сейчас — любой
студент может нажать кнопку ↻ в приложении.

## Установка на телефон

- **iPhone (Safari):** откройте ссылку → кнопка «Поделиться» → «На экран «Домой»».
- **Android (Chrome):** откройте ссылку → появится баннер «Добавить на главный экран»,
  либо через меню (⋮) → «Добавить на главный экран».

## Локальная разработка

```bash
npm install
npm run fetch-data   # тянет реальные данные с spb.ranepa.ru (нужен интернет)
npm run dev
```

`npm test` — офлайн-тесты парсера и сборки данных на зафиксированных примерах реальных
ответов сайта (не требуют сети).

## Известные ограничения

- **Год в датах.** В таблицах сайта указаны только день и месяц, без года. Год
  вычисляется по правилу «российский учебный год длится примерно с июля по июнь»:
  если скрипт запущен, например, в сентябре 2026, то месяцы июль–декабрь считаются
  2026 годом, а январь–июнь — 2027-м. Это может немного разъехаться в первые дни
  нового учебного года, если сайт публикует расписание сильно заранее.
- **Верстка сайта-источника.** Скрипт использует официальный REST API и находит нужные
  колонки по названию заголовка (а не по номеру), поэтому переживёт мелкие изменения
  верстки, но если РАНХиГС полностью перестроит структуру страниц расписания — парсер
  придётся обновить (см. `scripts/lib/parseSchedule.mjs`).
- Это неофициальное приложение, не связанное с РАНХиГС.
